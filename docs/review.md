# Test and benchmark review, 2026-10-07

The review covers 78 permanent test files: 76 `*_test.ts` files, including release and tooling controls and the memory filesystem fixture, plus two Playwright specs. Fixtures and ownership were traced through source, package docs, test guide, CI/tasks and architecture. Retained status below describes design review, not a claim that all runtime environments passed.

## Group dispositions

- RDF terms/Dataset/source: preserve semantic equality, graph and direction identity, collision-safe tuples, explicit Dataset insertion-order contract, exact estimates, caller abort identity, acquired iterator return and paired source/cleanup failures. Dataset property expected rows are independently projected; term properties compare input identity.
- RDF syntax: exact source ranges and canonical line escapes are public tooling/serializer contracts. Hostile UTF-8/chunk splits, token/depth bounds and tolerant statement atomicity are durable. Strengthened list graph and round-trip completeness assertions.
- RDF JSON-LD/canonicalization: exact expanded/compacted JSON shapes and canonical byte/digest goldens protect standards algorithms. Loader inspection found body/deadline, in-flight validation and cache-admission bugs; fixed production layer instead of accepting bad results.
- Ontology/SHACL: bounded source acquisition, cycles, superclass relationships, explicit alias policy and unsupported assertion retention are real contracts. Structured diagnostics and unknown over-depth paths preserve semantics.
- SPARQL: public primitive syntax/grammar brands, variable grammar and transport identity are intentional. Larger query/update/composition/Cypher/object patterns now compare independently parsed complete documents; only AST locations and BGP conjunction ordering are ignored. Multiplicity, clauses, operation order and terms remain exact.
- Vocab: collision planning, actual imported generated modules and Standard Schema result paths are useful. Temporary modules use unique directories and finally cleanup. Type-only official-contract assertions belong to CI checking and are not proven by --no-check.
- Triplestore: persisted format/generation names and recovery states are external durable contracts. Isolated in-memory fixtures deliberately simulate abrupt crashes; no owned OS handles exist. Seeded operation sequences compare against a separate Dataset model. _memory_test.ts is also a benchmark-owned measured fixture; the benchmark identity includes it.
- Engines/protocol/storage/browser: injected doubles test ownership and forwarding; actual pinned engines/services/native browser/KV/fs consumers provide separate real capability lanes. Containers/network/servers/temp roots/workers/Wasm stores have explicit cleanup. Browser storage tests use named capability skips and unique owned namespaces; failed partial writes already clean themselves.
- Conformance/release: negative controls challenge missing inputs/results, invalid statuses/kinds/graphs/imports/maps and stale source/revision identity. Temporary synthetic cases remain separate from official immutable corpora. Real Git/cache/release fixtures own disposable checkouts and never manipulate workspace Git. POSIX release fixture is deliberately skipped on Windows.

## Production findings

1. JSON-LD fetchDocument disposed deadline/caller listeners immediately after headers and read arrayBuffer without bounded admission. Pending bodies could hang beyond cancellation/deadline and oversized bodies materialized fully. Now chunks reads with the active composed signal, enforces bytes before another pull, cancels and unlocks on failure; timer stays owned through body consumption. Redirect/error/declared-oversize bodies are canceled.
2. createDocumentLoader stored the raw loader promise in inflight. A second waiter returned its oversized custom document without the first caller validation. The shared promise now includes byte validation/cache publication. Both reject, and failed documents are not cached.

3. Cached documents returned before byte admission. A cross-operation cache populated under a higher limit bypassed a stricter loader, and local caller-mutated documents could bypass the original limit. A shared admission helper now checks fresh outputs and every local/external cache hit. Rejection preserves the caller-owned cache and never reloads; exact-byte limits accept the original object. The cache option TSDoc makes byte policy explicit. Custom-loader interruption remains unchanged because its cancellation contract does not explicitly promise upstream interruption.

The `.mise/tasks/schema.ts` authoring task keeps the pinned Schema.org source size and Git blob identity checks.
Its response reader now admits at most four MiB before retaining each chunk, even without a truthful Content-Length;
the thirty-second deadline covers headers and body. This bounds retained response bytes, not Fetch's delivered chunk
or process RSS. Importing the task does not download or overwrite the generated vocabulary. The task-owned

cancellation, deadline coverage, reader unlock and primary/cleanup failures. No real network timing is part of these
controls; an uncooperative injected fetch or stream cancellation can still delay its own cleanup.

## Current tooling controls and validation

The private `artifacts.ts` helper binds six archives to current package/build input bytes and matching npm/JSR identities.
Consumer tasks reject missing receipts, substituted archives and stale installed payloads before running behaviors.
Installed payload comparison checks relative file paths and bytes, including missing or extra files; tar order and host
metadata are incidental. LF checkout rules keep the same package input bytes on Windows. Receipt controls deliberately
accept JSON key/row rearrangement and unrelated test/task edits, while rejecting changed build inputs and hidden runtime files.

The benchmark child collector bounds each direct child with an operational twenty-minute watchdog and each output stream
with a 32 MiB cap. It keeps exact stdout/stderr bytes, numeric exit codes, and separate startup/deadline errors.
Real child controls cover normal exit, nonzero exit, missing executable, invalid UTF-8 diagnostics and a stalled child.
These controls establish lifecycle and evidence fidelity; they do not assert measured throughput or latency.

The current local `deno task test` passed 70 package/conformance suites with 345 steps, then two tooling suites with
19 steps and one child suite. The final child suite passed five steps after raw-byte preservation was added. All local
runtime commands used `--no-check`; formatting and lint passed. Full type, conformance, installed archive, browser,
service and benchmark gates run on the exact reviewed source in CI. Their source commits and results belong to retained
ignored reports, so editing this document does not manufacture evidence for an unexecuted gate.
